# 横書き青空文庫ブラウザ版

[青空文庫](https://www.aozora.gr.jp/)の作品を、パソコン・タブレット・スマホのブラウザで読みやすい横書きで表示するリーダーです。HTML・CSS・JavaScript だけで動く静的サイトで、GitHub Pages で公開しています。

**サイト：https://manpukuichiro.github.io/aozora-yokogaki/**

- 人気作品 100 本を収録しているほか、青空文庫の全作品（約 1 万 8 千作品）から探して、ダウンロードした zip を読み込めます。
- ルビ・傍点・見出し・字下げなど、青空文庫の記法を表示します（Android 版「青空文庫リーダー」の処理を移植）。
- 文字の大きさ・行間・行の長さ・書体・配色を変えられ、読書位置は自動で保存されます。

**現状（2026-10-28）**：公開リポジトリ `manpukuichiro/aozora-yokogaki` から GitHub Pages で公開しています。`main` に push すると自動で更新されます（[公開](#公開github-pages)を参照）。不具合の報告や要望は [Issues](https://github.com/manpukuichiro/aozora-yokogaki/issues) へどうぞ。

## 出典と権利

- **本文**：`texts/aozora_*.txt` は、青空文庫で公開されているテキストファイルを加工せずに収録したものです（Shift_JIS、末尾に底本と入力・校正をされた方の情報つき）。青空文庫の作品一覧で、作品著作権フラグと関係者全員の人物著作権フラグが「なし」の作品だけを収録しています。利用は[青空文庫収録ファイルの取り扱い規準](https://www.aozora.gr.jp/guide/kijyunn.html)に従います。日本の書誌情報に基づく選定であり、海外での権利の消滅を保証するものではありません。
- **書誌データ**：`data/catalog.json` と `texts/index.json` は、青空文庫の[作品一覧 CSV](https://www.aozora.gr.jp/index_pages/list_person_all_extended_utf8.zip)を基に、項目の抽出・作品の選定・表記の整形・JSON 化をしたものです。提供元：青空文庫。ライセンス：[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)。
- **作品の選定**：青空文庫の[アクセスランキング](https://www.aozora.gr.jp/access_ranking/)（2022 年・XHTML 版）を使っています。
- **プログラム**：プログラム・付属ドキュメント・開発用スクリプトは [Apache License 2.0](LICENSE) で提供します。Copyright 2026 Manpuku Ichiro. Apache License 2.0 は、青空文庫の本文と書誌データには適用しません。
- **利用者向けの説明**：出典・権利・通信・不具合の報告先（GitHub Issues）は [NOTICE.html](NOTICE.html) に書いています。青空文庫の公式サービスではありません。

作品を入力・校正し、公開を続けている青空文庫のみなさまに感謝します。

## 開発

### ローカルで確認する

`fetch` を使うため、`index.html` をダブルクリックで開く（file://）のではなく、ローカルサーバー経由で開きます。

```bash
python -m http.server 8765 --directory .
```

ブラウザで http://localhost:8765/ を開きます。手元のファイルをそのまま配信すると、ブラウザに古い CSS や JavaScript が残ることがあります。公開物と同じ条件（読み込む URL にハッシュ付き）で確かめたいときは、`python tools/build_site.py --out _site` で作った `_site` を配信します。

スマホで確かめるときは、PC とスマホを同じ Wi-Fi につなぎ、`--bind 0.0.0.0` で起動したサーバーに PC の LAN 内の IP アドレスでアクセスします。HTTPS ではないため `crypto.subtle` が使えず、同じ zip を読み込み直すと本棚に 2 冊並ぶことがあります。

### テスト

```bash
node --test dev/reader.test.js dev/safety.test.js   # 検索・著者の絞り込み・取り込み・読書位置・zip の安全性などの回帰テスト
node dev/aozora.test.js                             # 青空文庫記法の解析を Android 版の例と照合する
```

`dev/` にはほかに、動作確認用のテキスト（`dev/fixtures/`：ルビ・注記と目次・記法なし・Shift_JIS）、読み込みを試すテスト用 zip を `dev/zips/` に作る `dev/make_test_zips.py`、実際のブラウザで安全性を確かめる `dev/browser-safety.cjs`（Playwright と Edge が必要）があります。テスト用のファイルは画面にドラッグ＆ドロップして確かめ、確認後は本棚の「本棚から削除」で消します。

### データとアイコンを作り直す

| コマンド | 内容 |
|---|---|
| `python tools/fetch_popular.py` | 収録作品（本文と `texts/index.json`）を取得する |
| `python tools/build_catalog.py` | 全作品の目録 `data/catalog.json` を作る（作品一覧 CSV と、人気順に使うアクセスランキングを取得。`--ranking` で変更可、既定 `2022_xhtml`）。あわせて `data/authors.json` も作る。`--authors-only` なら通信せず、今の目録から `data/authors.json` だけを作り直す |
| `python tools/make_favicon.py` | アイコン 3 種を作る（標準ライブラリだけで動く） |

**収録作品の選び方（`fetch_popular.py`）**
- 青空文庫のアクセスランキング（既定は 2022 年の XHTML 版。年間ランキングはこれが最新）を上から見て、100 作品を選びます。
- 作品著作権フラグと、関係者全員（著者・翻訳者など）の人物著作権フラグがすべて「なし」の作品だけを採ります。
- 同じ題名・同じ著者の別の版（新字新仮名と旧字旧仮名など）は、順位が上の版だけを採ります。
- 本文は公式の zip から取り出したまま保存します。`texts/index.json` には、本文の SHA-256・配布元（`sourceZip`）・取得日時（`downloadedAt`）・権利フラグの確認日（`rightsCheckedAt`）も記録します。
- 次回の実行では、記録済みで本文も書誌の本文更新日も変わっていない作品は再利用し、それ以外は取り直します。`--force` ですべて取り直せます。リクエストの間隔は 1 秒です。
- `--count`（本数）、`--ranking`（例 `2021_xhtml`、`2022_txt`）、`--dry-run`（選定結果の表示だけ）を指定できます。
- `texts/index.json` は毎回作り直します。収録作品を増やすときは `--count` や `--ranking` で調整します。手で作品を足しても、公開用ビルドは「ファイル名が `aozora_<6 桁の作品ID>.txt` であること」「目録で著作権フラグが『なし』であること」を確かめるので、条件に合わない作品があると止まります。

目録と収録作品は自動では更新されません。青空文庫には作品が随時追加されるので、ときどき作り直してください。

## 公開（GitHub Pages）

公開は GitHub Actions（`.github/workflows/pages.yml`）で行います。

- `main` への push と手動実行で、`python tools/build_site.py --out _site` を実行します。このスクリプトがテストと、権利フラグ・重複・本文ハッシュ・目録の形と大きさ・著者の候補が目録と合っているかの検証を行い、どれかが失敗すると公開しません。
- 成功したときだけ、生成した `_site/` を GitHub Pages に公開します。リポジトリ全体（`dev/`・`tools/`・README など）は公開しません。
- pull request では、テストとビルドだけを行い公開しません。リポジトリを非公開に戻した場合も、公開の手順は飛ばします（無料プランでは非公開リポジトリから Pages を公開できないため）。
- 使う環境：Node 24、Python 3.12（どちらも標準機能だけで、追加のパッケージは不要）。

**公開の設定**（2026-10-28 に実施済み。作り直すときの控え）
1. GitHub の Settings → General のいちばん下の「Change visibility」で Public にする。
2. Settings → Pages の Source を「GitHub Actions」にする（「Deploy from a branch」にするとリポジトリ全体が公開されるので選ばない）。
3. Actions タブで「GitHub Pages」のワークフローを手動で実行する（または次に push する）。
4. `https://manpukuichiro.github.io/aozora-yokogaki/` で開けることを確かめる。不具合の報告先の Issues は、Settings → General → Features で有効になっていることを確かめる（新しいリポジトリでは既定で有効）。

公開後に確かめたこと（2026-10-28、PC の Chromium 系ブラウザ）：最新の版番号の表示、収録作品の本文とルビ、目録の検索と著者の絞り込み、`dev/`・`tools/`・README が公開物に含まれないこと。目録は gzip で配信され、転送量は約 0.7MB。

まだ確かめていないこと：Firefox・Safari、iPhone・Android の実機、キーボード操作、200% 拡大での表示、本棚の URL、zip と txt の読み込み。

アクセス解析は入れていないため、訪問者数や転送量はわかりません（GitHub Pages は所有者に転送量を示さず、目安の月 100GB を大きく超えたときに連絡が来るだけです）。

### 公開物の作り方（`tools/build_site.py`）

- 出力先は、まだないフォルダを指定します（既存の出力は上書きしません）。生成時に通信はしません。
- 目録 `data/catalog.json` に必要な列（人気順に使う `rank` を含む）がそろい、各行の列の数が合い、順位のある作品があり、大きさが 4MB 以下であることを確かめます。検索を始めると目録全体を読み込むため、作り直して急に重くなったときは止めます。
- 実行に必要なファイル・アイコン・`NOTICE.html`・`LICENSE` と、一覧に含まれる本文だけをコピーします。`manifest.json` に、版と各ファイルのサイズ・SHA-256 を記録します。
- 検索エンジン向けに、トップページと収録作品のページ（`?text=aozora_<作品ID>.txt`）を並べた `sitemap.xml` を作ります。Google Search Console の「サイトマップ」から `sitemap.xml` を送信します。`robots.txt` はドメインの直下にしか置けないため使いません。
- 公開物だけで、次の書き換えをします（手元のファイルは変えません）。
  - **版番号**：`<span class="build-version">開発版</span>` を、ビルドした日（日本時間）とコミットの短い ID に置き換えます（例 `2026.10.28（c85c9e6）`）。GitHub Actions では `GITHUB_SHA` を使います。
  - **LICENSE**：拡張子のない `LICENSE` はリンクを押すとダウンロードになるため、`LICENSE.txt` としても置き、ページからのリンクをそちらに向けます。
  - **読み込む URL のハッシュ**：HTML が読み込む CSS・JavaScript・アイコンの URL に内容のハッシュを付けます（例 `reader.js?v=efe94f4528`）。GitHub Pages はファイルを 10 分ほどキャッシュさせますが、中身が変わったファイルは URL も変わるので、新しい HTML と古い JavaScript が組み合わさりません。
- JavaScript が読み込むデータ（`texts/index.json`・本文・目録）は、毎回サーバーに更新を確かめます（`cache: 'no-cache'`。変わっていなければ 304 の応答だけ）。
- 残る制約：HTML 自体もキャッシュされるため、更新直後にまれに古い HTML のまま新しいファイルを読み込むことがあります。再読み込みすれば直ります。

## 仕様の詳細

### 画面と URL

| URL | 表示 |
|---|---|
| `./` | ホーム |
| `./?text=aozora_000773.txt` | 収録作品（`texts/` のファイル名） |
| `./#book=<ID>` | 本棚の作品。このブラウザに保存されていなければ、お知らせつきでホームを表示（`#` 以降はサーバーに送られない。旧形式の `?book=` も読み取って置き換える） |

この README の「収録作品」（`texts/` に入れてサイトで配信する 100 作品）は、画面では「**すぐに読める作品**」と表記します（ダウンロードせずに読めることが伝わるように）。zip をダウンロードして読む作品は「青空文庫のほかの作品」と呼びます。

- **ホーム**：サイトの紹介、「作品を探す」「ファイルを開く…」、青空文庫の全作品から探す検索欄、続きから読む（最近読んだ順に最大 10 作品と、それぞれの読書位置。「一覧から外す」で外せ、作品と読書位置は残る）、本棚、すぐに読める作品（収録作品）の上位 12 作品、使い方、このサイトについて、開発者による関連アプリ。文面は `index.html` の `#home` に直接書いてあります。ツールバー左端のサイト名でいつでも戻れます。
- **作品を探す**：ツールバーの作品名を押すと開きます。検索欄が空のときは、上から「著者から探す」（青空文庫での作品数が多い著者 100 人（`data/authors.json`）から、ページを読み込むたびにランダムに 10 人を選んで出す。選ぶ人を固定しないのは、選び方の偏りを避けるため。ページを開いている間は選び直さず、再読み込みで選び直す。共著の作品は数えない。押すとその著者に絞り込む）、本棚、収録作品を表示します（全作品の目録は、検索語が入るまで読み込まない）。収録作品は「人気順」と「著者別」を切り替えられます（前回の選択を覚えます）。その右端の「DLしたファイルを開く…」で、ダウンロードした zip・txt を選ぶと、ポップアップを閉じて読み込みます（幅 480px 以下ではボタンの文字を 2 行にして同じ行に収める）。検索欄では、作品名・副題・著者名・訳者名とその読みがなで絞り込み、青空文庫の全作品からも探します。全作品の検索結果は「人気順」（ランキングにある作品を順位の順に先に出し、残りは作品名の一致度の順）と「50音順」（作品名の読みの順）を切り替えられます（前回の選択を覚えます）。ひらがなとカタカナ、全角と半角の違いは無視し、空白で区切ると AND 検索になります（例：「猫 漱石」）。Enter でいちばん上の作品を開きます。収録作品（人気順）・本棚・全作品の検索結果で著者名を押すと、その著者の作品だけに絞り込みます（作品名などに著者名を含む、ほかの著者の作品は除く。検索欄を書き換えると解除）。
- **目次**：ツールバーの「目次」で開きます。青空文庫の見出し注記（大・中・小見出し、窓見出し、同行見出し）から作り、いま読んでいる箇所の見出しを強調します。見出しのない作品では「目次なし」と表示して押せません。
- **表示設定**：文字サイズ・行間・行の長さ、書体（明朝・ゴシック）、太さ（300〜700）、ルビの表示・非表示、配色（端末に合わせる・白・セピア・黒）、表示設定を元に戻す。書体は端末に入っているフォントを使い、外部からは読み込みません（以前選べた Web フォントの Noto・BIZ UD は外しました。保存済みの設定でそれらを選んでいた場合は明朝で表示します）。太さは OS にある太さが使われるため、表示したときに太さごとの文字の濃さを測り、その端末で見た目が変わる段階だけを選択肢に出します（例：Windows の明朝は 300・400・700 の 3 段階。測れない環境では 300〜700 をすべて出します）。
- **読書位置**：作品ごとに自動で保存し、次に開いたときは続きから表示します。「段落番号＋段落内の割合」で保存するため、文字サイズや画面幅を変えても同じ箇所に戻ります。

### 作品の読み込みと本棚

1. 「作品を探す」やホームの検索欄で作品を探し、「zip をダウンロード」で青空文庫からテキストの zip を保存する（同じタブのままダウンロードする）。
2. パソコンでは画面にドラッグ＆ドロップするか、「ファイルを開く…」（「作品を探す」の中では「DLしたファイルを開く…」）から選ぶ。スマホ・タブレットでは、「zip をダウンロード」を押した作品の欄に出る「開く…」から選ぶ（iPhone・iPad では「ファイル」アプリの「ダウンロード」フォルダに保存される）。

- zip は展開せずに読めます。中の .txt が複数あるときは一番大きいものを本文とみなします。展開済みのテキスト（Shift_JIS／UTF-8）も読めます。
- 配布 zip のファイル名（例 `773_ruby_5968.zip`）から作品ID を読み取り、目録の正確な作品名・著者で本棚に登録し、図書カードへのリンクも付けます。作品ID のないファイルは、本文冒頭の「作品名／（副題）／著者名」から推定します。
- 作品ID が同じなら、本文が更新されていても同じ作品として置き換え、読書位置を引き継ぎます。作品ID がなく、同じファイル名で本文が変わった場合は、置き換えるか確認します（キャンセルすると別の作品として保存）。
- 読み込んだ作品は「本棚」としてこのブラウザ（IndexedDB）に保存します。本文はどこにも送信しません。本棚の各作品の「本棚から削除」で、保存した本文と読書位置を消せます（確認のうえ消し、元に戻せない。また読むときは zip を読み込み直す）。
- 上限：1 ファイル 5 MiB（zip の展開後・UTF-8 変換後も同じ）、30,000 行、一度に 20 ファイル、zip 内は 256 ファイルまで。zip の構造・サイズ・CRC を検証し、実際の展開量も制限します。
- 青空文庫の公式サーバーは他サイトからの読み込みを許可していない（CORS）ため、ダウンロードしてから読み込む手順を取っています。GitHub 上にあった公式ミラー（`aozorabunko/aozorabunko`）は 2026-10 時点で公開されておらず、有志の複製（`aozorahack/aozorabunko_text`）は 2023 年から更新されていないため、そこから直接読み込む方式は採っていません。
- 全作品の目録（`data/catalog.json`、約 2.7MB。gzip 配信で転送は約 0.7MB）は、検索を始めたときに一度だけ読み込みます。取得に失敗した場合は「目録を再読み込み」で再試行できます。目録には、著作権が存続していて青空文庫が許諾を得て公開している作品（約 500 作品）も含みます。これらはユーザーが自分でダウンロードして読むためのもので、サイトには収録していません。

### スマホ・タブレット

- **幅 600px 以下（スマホ）**：ツールバーを 1 段（サイトのアイコン・作品名・目次・表示設定）にまとめ、「ファイルを開く…」「作品情報」「青空文庫」は表示設定の「その他」に移します。読書位置はツールバー下端の細いバーで示します。表示設定は画面の半分ほどに収め、パネルの中でスクロールします。
- **スマホとタッチ操作の端末（タブレット）**：作品を読んでいるときは、下へ読み進めるとツールバーを隠し、上へ戻すと出します（表示設定を開いている間とページ先頭付近では隠さない）。本文をタップすると表示設定を閉じます。
- **タッチ操作の端末**：押せる範囲を 44px 以上にし、入力欄の文字を 16px にして iPhone で入力時に画面が拡大されるのを防ぎます。外字の ※ をタップすると注記の説明を画面下に出します。「作品を探す」を開いても検索欄には入らず、画面キーボードで一覧が隠れないようにします。タップの後にホバーの色が残らないようにし、押している間だけ色を付けます。
- **ブラウザの帯の色**：`theme-color` を、選んでいる配色の背景色に合わせます。
- **iPhone の画面の切り欠き・ホームバー**：`viewport-fit=cover` と `env(safe-area-inset-*)` で、ツールバーや本文が重ならないようにしています。
- **ホーム画面に追加**：apple-touch-icon と短い名前（横書き青空文庫）を用意しています。全画面で起動するアプリ化（PWA の standalone 表示）はしていません。iOS の全画面表示では「zip をダウンロード」からの保存がうまく動かない可能性があるためです。

### 青空文庫記法

Android 版「青空文庫リーダー」の `TextProcessor`（ルビ処理と `AozoraAnnotationParser`）を移植しています。本文に `《`・`｜`・`※`・`［＃` のいずれかがあるときだけ、青空文庫形式として扱います。冒頭の【テキスト中に現れる記号について】（区切り線で囲まれたブロック）は表示しません。

**ルビ**
- `｜親文字《よみ》`：明示ルビ。対応する《》がない `｜` は表示しません。
- `漢字《よみ》`：《 の直前から同じ文字種（漢字／ひらがな・カタカナ／半角英数字）が続く範囲を親文字にします（最大 20 字）。
- `刺※《しらく》`：外字の ※ は、直前の漢字列とまとめて親文字にします。
- 外字注記 `※［＃…］` は ※ を残し、マウスを重ねるか、タップすると注記の説明を表示します。
- ルビが親文字より長くても本文の字間は広げず、ルビを左右にはみ出させます。同じ行で隣のルビと重なるときはまとめて詰め直し、本文の段の端からは出しません（Android 版の `RubyCollisionResolver` の移植）。漢字の親文字どうしがかな・読点だけを挟んで並ぶときは、ルビの間を半角分あけます。
- 行間を狭くすると（1.7 未満が目安）、ルビのある行だけ少し広がります（ルビが前の行の文字と重ならないようにするため）。
- ルビの位置の計算は画面の近くの段落だけで行い、残りはスクロールで近づいたときに行います（数千か所のルビがある長編でも表示設定の変更が重くならないように）。
- コピーすると `漢字《かんじ》` の形になります（ルビ非表示のときは親文字だけ）。

**注記**

| 注記 | 表示 |
|---|---|
| 大・中・小見出し、同行見出し（前方参照・範囲指定） | 太字（Android 版と同じく文字の大きさは変えない） |
| 窓見出し | 本文 2 行分を占めて左に置き、本文を回り込ませる |
| ○字下げ、ここから○字下げ、折り返して○字下げ、改行天付き | 段落の字下げ（ぶら下げ含む） |
| 地付き、地から○字上げ、ページの左右中央 | 右寄せ（字上げ分の全角空白を補う）、中央寄せ |
| 傍点（各種） | 圏点（ゴマ点。種類は区別しない） |
| 傍線・波線など | 下線（種類は区別しない） |
| 太字、斜体、○段階大きな／小さな文字、上付き・下付き小文字 | 文字の装飾（1 段階 1.2 倍） |
| 「ママ」の注記 | （ママ）を小さく上付きで添える |
| 割り注 | 括弧付きの小さな文字 |
| 罫囲み（語・範囲） | 枠線。範囲の罫囲みは字下げ・字詰めの幅に合わせる |
| ○字詰め | その字数で折り返す（CSS の最大幅で実現） |
| キャプション、挿絵（○○入る） | 小さめの斜体で中央寄せ。挿絵は［図版：説明］と表示 |
| 改ページ・改丁・改段・改見開き | 2 行分の余白 |
| 縦中横・横組み | 横書きなので何もしない |

上記以外の注記は表示しません。注記だけの行は、Android 版と同じく空行として残ります。

### 保存・通信・セキュリティ

- 保存先は、配信パスごとに分けた IndexedDB（本棚）と localStorage（表示設定・読書位置・最近読んだ作品）です。別の端末やブラウザ、別のアドレスには引き継がれません。ブラウザのデータ消去・プライベート閲覧・容量不足などで消えることがあり、保存に失敗したときは画面に知らせます。
- 同じ GitHub アカウントの別のプロジェクトページとは同じオリジンになります。保存名を分けているのは取り違えを防ぐためで、別サイトからのアクセスを防ぐものではありません。
- 本文のアップロード機能はありません。通信するのは配信元（GitHub Pages）だけで、外部のフォントなどは読み込みません。GitHub Pages のアクセスログについては NOTICE.html に書いています。
- CSP は、スクリプト・スタイル・フォント・接続をすべて同じサイト（`'self'`）に限ります。本文の装飾のためインラインスタイルは許可しています。meta 要素の CSP では、フレーム埋め込みの制限など、HTTP ヘッダーでしかできない指定は代替できません。
- オフラインでの起動は保証していません。
