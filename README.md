# 横書き青空文庫ブラウザ版

GitHub Pages などの静的ホスティングにそのまま置けるブラウザ用の横書きリーダーです。

## 出典

- 収録作品の本文（`texts/aozora_*.txt`）は、[青空文庫](https://www.aozora.gr.jp/)で公開されているテキストファイルを、加工せずにそのまま収録したものです。各ファイルの末尾に、底本と入力・校正をされた方の情報があります。
- 収録しているのは、青空文庫の作品一覧で作品著作権フラグと関係者全員の人物著作権フラグが「なし」の作品だけです。利用は[青空文庫収録ファイルの取り扱い規準](https://www.aozora.gr.jp/guide/kijyunn.html)に従います。
- 作品の選定には、青空文庫の[アクセスランキング](https://www.aozora.gr.jp/access_ranking/)（2022 年・XHTML 版）を使っています。
- 作品を入力・校正し、公開を続けている青空文庫のみなさまに感謝します。

```
dev/              開発用（照合テスト、動作確認用のテキスト、テスト用 zip の作成）
.github/workflows/pages.yml  GitHub Pages への公開（テストと build_site.py の成功を条件に、生成物だけを公開）
.nojekyll         GitHub Pages で Jekyll の変換を止める（空ファイル）
```

## ローカルで確認する

`fetch` を使うため、`index.html` をダブルクリックで開く（file://）のではなく、ローカルサーバー経由で開きます。

```bash
python -m http.server 8765 --directory .
```

ブラウザで http://localhost:8765/ を開きます。

## 青空文庫の作品を読む（ユーザーが読み込む）

1. 青空文庫の図書カードから「テキストファイル（ルビあり）」の zip をダウンロードする。
2. リーダーの画面にドラッグ＆ドロップするか、「ファイルを開く…」から選ぶ（複数まとめても可）。

- zip は展開せずにそのまま読めます。中の .txt が複数あるときは一番大きいものを本文とみなします。展開済みのテキスト（Shift_JIS／UTF-8）も読めます。
- 読み込んだ作品は「本棚」としてこのブラウザ（IndexedDB）に保存され、次回からは「作品を探す」の「本棚」から開けます。本文はどこにも送信しません。
- 作品名と著者名は、テキスト冒頭の「作品名／（副題）／著者名」から推定します。
- 青空文庫の配布 zip は作品IDで識別し、本文の長さが変わっても同じ作品として更新して読書位置を引き継ぎます。本文が同一のファイルも既存の登録を再利用します。
- 作品IDがなく、同じファイル名・作品名・著者名で本文が変わった場合は、置き換えるか確認します。キャンセルすると別作品として保存します。同名・同文字数だけでは上書きしません。既存の本棚のIDと読書位置は維持します。
- ホームや「作品を探す」の本棚で、作品の横にある「削除」から消せます。確認後に本文と読書位置を削除します。
- プライベートウィンドウなど保存できない環境では、その場で表示だけします。

## 青空文庫の全作品から探す

ホームの検索欄、または「作品を探す」の検索欄で、収録作品と本棚に加えて、青空文庫の全作品（約 1 万 8 千作品）から探せます。

- 結果には「zip をダウンロード」（青空文庫の配布 zip への直接リンク）と「作品情報」のリンクが出ます。ダウンロードした zip を画面にドラッグ＆ドロップすると読めます。本文は青空文庫のサーバーから直接は読めないため（CORS）、この手順を取っています。
- 「zip をダウンロード」は同じタブのままダウンロードします（新しいタブを開くと iOS で空のタブが残るため）。押した作品の欄には「開く…」ボタンと案内が出て、そこからダウンロードした zip を選べます（スマホ・タブレット向け。ポップアップ表示中はツールバーの「ファイルを開く…」を操作できないので、専用の入力欄を置いている）。
- GitHub 上にあった青空文庫の公式ミラー（`aozorabunko/aozorabunko`）は 2026-10 時点で公開されておらず、有志の複製（`aozorahack/aozorabunko_text`）は 2023 年から更新されていないため、そこから直接読み込む方式は採っていません。
- 収録作品・本棚にある作品は、全作品側の結果からは除いて表示します。
- 空白で区切った語はAND検索になります（例：「猫 漱石」）。作品名・著者名など別々の項目に含まれる語も組み合わせられます。
- 目録の取得に失敗した場合は自動再試行を止め、「目録を再読み込み」で再試行できます。
- 目録（`data/catalog.json`、約 2.7MB。gzip によるローカル試算は約 0.7MB、実配信の転送量は未確認）は、検索を始めたときに一度だけ読み込みます。
- 配布 zip のファイル名（例 `773_ruby_5968.zip`）から作品ID を読み取り、本棚には目録の正確な作品名・著者で登録します。図書カードへのリンクも付きます。
- 目録には、著作権が存続していて青空文庫が許諾を得て公開している作品（約 500 作品）も含みます。これらはユーザーが自分でダウンロードして読むためのもので、サイトには収録していません。

目録を作り直すには：

```bash
python tools/build_catalog.py
```

## 収録作品（人気作）

`texts/aozora_*.txt` と `texts/index.json` は `tools/fetch_popular.py` で生成しています。

```bash
python tools/fetch_popular.py
```

- 青空文庫のアクセスランキング（既定は 2022 年の XHTML 版。年間ランキングはこれが最新）を上から見て、100 作品を選びます。
- 公式の作品一覧 CSV で、作品著作権フラグと、関係者全員（著者・翻訳者など）の人物著作権フラグがすべて「なし」の作品だけを採ります。著作権が存続していて許諾を得て公開されている作品は含めません。
- 同じ題名・同じ著者の別の版（新字新仮名と旧字旧仮名など）は、順位が上の版だけを採ります。
- 本文は公式の zip から取り出したまま（Shift_JIS、末尾の底本・入力・校正の情報つき）で保存し、加工しません。
- `texts/index.json` に、本文の SHA-256・配布元（`sourceZip`）・取得日時（`downloadedAt`）・権利フラグの確認日（`rightsCheckedAt`）を記録します。
- 次回の実行では、取得日時とハッシュが記録済みで、本文のハッシュも書誌の本文更新日も変わっていない作品は再利用し、それ以外（本文が更新された作品、記録のない作品）は取り直します。`--force` ですべて取り直せます。リクエスト間隔は 1 秒です。
- `--count`（本数）、`--ranking`（例 `2021_xhtml`、`2022_txt`）、`--dry-run`（選定結果の表示だけ）を指定できます。
- `texts/index.json` は毎回作り直します。手で足した作品は消えるので、自前の作品を収録する場合はスクリプトに組み込むか、別のファイルで管理してください。

## 開発用（dev/）

```bash
node dev/aozora.test.js          # 青空文庫記法の解析を Android 版の例と照合する
node --test dev/reader.test.js   # 検索・取り込み・通信失敗・読書位置の回帰テスト
python dev/make_test_zips.py     # 読み込み機能を試す zip などを dev/zips/ に作る（git には入れない）
```

- `dev/fixtures/` には動作確認用のテキストがあります。`ruby-test.txt`（ルビ）、`annotation-test.txt`（注記・目次）、`sample.txt`（記法なしの文章）、`sample-sjis.txt`（Shift_JIS の判定）です。
- ブラウザで確かめるときは、これらのファイルや `dev/zips/` のファイルを画面にドラッグ＆ドロップします（本棚に入るので、確認後は本棚の「削除」で消せます）。
- 公開候補は `tools/build_site.py` で生成します。`dev/`・`tools/`・一覧から外れた本文は含みません。

## ホーム（最初のページ）

URL で作品を指定せずに開くと、ホームを表示します。ツールバー左端のサイト名でいつでも戻れます。ホームの文面は `index.html` の `#home` に直接書いてあります。

- サイトの紹介、「作品を探す」「ファイルを開く…」、青空文庫の全作品から探す検索欄
- 履歴があるときは紹介文より上に「続きから読む」を表示（最近読んだ順に最大5作品。それぞれの保存位置を表示し、続きから再開。以前の最後の1作品も引き継ぎます）
- 本棚（読み込んだ作品がある場合。「本棚をすべて見る」で全件を表示）と、収録作品から（収録作品の上位 12 作品）
- 使い方、このサイトについて（収録方針・表示できる記法・プライバシー・動作環境）、青空文庫への謝辞

URL の形式：

| URL | 表示 |
|---|---|
| `./` | ホーム |
| `./?text=aozora_000773.txt` | 収録作品（`texts/` のファイル名） |
| `./#book=<ID>` | 本棚の作品。このブラウザに保存されていなければ、お知らせつきでホームを表示 |

## 「作品を探す」の画面

ツールバー左の作品名を押すと、「作品を探す」が開きます。

- 本棚（読み込んだ作品）と収録作品を表示します。収録作品は「人気順」と「著者別」を切り替えられます（前回の選択を覚えます）。
- 検索欄で作品名・副題・著者名・訳者名とその読みがなを絞り込めます。ひらがな・カタカナ、全角・半角の違いは無視します。Enter でいちばん上の作品を開きます。

## 作品を追加する（サイトに収録する）

通常は `tools/fetch_popular.py` の `--count` や `--ranking` で調整します。手で追加する場合は次のとおりですが、スクリプトを実行すると `texts/index.json` は作り直されるので注意してください。

1. 本文を `texts/` に置く（ファイル名は半角英数字・`-`・`_`・`.` のみ、拡張子 `.txt`）。
2. `texts/index.json` に追記する。

```json
{ "file": "wagahai.txt", "title": "吾輩は猫である", "author": "夏目漱石" }
```

- 文字コードは UTF-8 推奨。UTF-8 として読めない場合は Shift_JIS（青空文庫の配布形式）として読みます。
- `?text=ファイル名.txt` で特定の作品を直接開けます。

## 機能

- 横書き表示、行の長さ・文字サイズ・行間の調整、配色（端末に合わせる／白／セピア／黒）
- 書体の選択：明朝、ゴシック（端末に入っているフォントを使い、外部からフォントは読み込まない）
  - 以前は Web フォント（Noto Serif JP・Noto Sans JP・BIZ UD明朝・BIZ UDゴシック、Google Fonts から読み込み）も選べましたが、外部への通信をなくすため外しました。保存済みの設定でそれらを選んでいた場合は明朝で表示します。
  - 追加・変更は `reader.js` の `FONTS` を編集します。
- 太さ（ウェイト）の選択：300〜700
  - OS にある太さが使われるため、環境によっては見た目が変わらない段階があります。
  - 選んだ太さがないフォントに切り替えると近い太さで表示し、元のフォントに戻すと選んだ太さに戻ります。
- 目次：画面上部の作品名の隣にある「目次」ボタンでポップアップ表示。スクロール中も表示され、項目を押すとその見出しへ移動します
  - 青空文庫の見出し注記（大・中・小見出し、窓見出し、同行見出し）から作ります（Android 版と同じ）。見出しのない作品ではボタンが押せません
  - 開くと、いま読んでいる箇所の見出しが強調され、その位置までスクロールします
  - Esc キー、「閉じる」、ポップアップの外側を押すと閉じます
- 表示設定と作品ごとの読書位置をブラウザの localStorage に保存（端末・ブラウザ間では共有されません）
- 読書位置は「段落番号＋段落内の割合」で保存するため、文字サイズを変えても同じ箇所に戻ります

## スマホ・タブレット

- **幅 600px 以下（スマホ）**：
  - ツールバーは 1 段（サイトのアイコン・作品名・目次・表示設定）にまとめます。
  - 「ファイルを開く…」「作品情報」「青空文庫」は、表示設定の「その他」に移ります。
  - 読書位置は数字の代わりに、ツールバー下端の細いバーで示します。
  - 作品を読んでいるときは、下へ読み進めるとツールバーを隠し、上へ戻すと出します。表示設定を開いている間と、ページ先頭付近では隠しません。
  - 表示設定は画面の半分ほどに収め、パネルの中でスクロールします。本文をタップすると閉じます。
- **タッチ操作の端末（スマホ・タブレット）**：
  - ボタンやリンクの押せる範囲を 44px 以上にします。
  - 入力欄の文字を 16px にして、iPhone で入力時に画面が拡大されるのを防ぎます。
  - 外字の ※ をタップすると、注記の説明を画面下に表示します。
  - 「作品を探す」を開いても検索欄には入らず、画面キーボードで一覧が隠れないようにします。
- **ツールバーの自動非表示・本文のタップで表示設定を閉じる**：幅の狭い画面に加えて、タッチ操作の端末（タブレット）でも働きます。
- **タップの見た目**：タッチ操作の端末ではホバーの色を付けず（タップ後に色が残らないように）、押している間だけ色を付けます。タップ時の色付きの四角も控えめにしています。
- **ブラウザの帯の色**：`theme-color` を、選んでいる配色（白・セピア・黒、端末に合わせる）の背景色に合わせて書き換えます。
- **ホーム画面に追加**：apple-touch-icon と、追加したときの短い名前（`apple-mobile-web-app-title`：横書き青空文庫）を用意しています。全画面で起動するアプリ化（PWA の standalone 表示）はしていません。iOS の全画面表示では「zip をダウンロード」からの保存がうまく動かない可能性があるためです。
- **iPhone の画面の切り欠き・ホームバー**：`viewport-fit=cover` と `env(safe-area-inset-*)` で、ツールバーや本文が重ならないようにしています。
- **作品の読み込み**：ドラッグ＆ドロップはパソコンだけです。スマホ・タブレットでは、「zip をダウンロード」で保存したファイルを「ファイルを開く…」から選びます。

## 青空文庫記法

Android 版「青空文庫リーダー」の `TextProcessor`（ルビ処理と `AozoraAnnotationParser`）を移植しています。本文に `《`・`｜`・`※`・`［＃` のいずれかがあるときだけ青空文庫形式として扱います。

### ルビ

- `｜親文字《よみ》`：明示ルビ。対応する《》がない `｜` は表示しません。
- `漢字《よみ》`：《 の直前から同じ文字種（漢字／ひらがな・カタカナ／半角英数字）が続く範囲を親文字にします（最大 20 字）。
- `刺※《しらく》`：外字の ※ は直前の漢字列とまとめて親文字にします。
- 外字注記 `※［＃…］` は ※ を残し、マウスを重ねると注記の説明を表示します。
- 冒頭の【テキスト中に現れる記号について】（区切り線で囲まれたブロック）は表示しません。
- 表示設定の「ルビ」で表示／非表示を切り替えられます。コピーすると `漢字《かんじ》` の形になります（非表示のときは親文字だけ）。
- ルビが親文字より長くても本文の字間は広げず、ルビを左右にはみ出させます。同じ行で隣のルビと重なるときはまとめて詰め直し、本文の段の端からは出しません（Android 版の `RubyCollisionResolver` の移植）。漢字の親文字どうしがかな・読点だけを挟んで並ぶときは、ルビの間を半角分あけます。
- 行間を狭くすると（1.7 未満が目安）、ルビのある行だけ少し広がります（ルビが前の行の文字と重ならないようにするため）。
- ルビの位置の計算は画面の近くの段落だけで行い、残りはスクロールで近づいたときに行います（数千か所のルビがある長編でも表示設定の変更が重くならないように）。

### 注記

| 注記 | 表示 |
|---|---|
| 大・中・小見出し、同行見出し（前方参照・範囲指定） | 太字（Android 版と同じく文字の大きさは変えない） |
| 窓見出し | 本文 2 行分を占めて左に置き、本文を回り込ませる |
| ○字下げ、ここから○字下げ、折り返して○字下げ、改行天付き | 段落の字下げ（ぶら下げ含む） |
| 地付き、地から○字上げ、ページの左右中央 | 右寄せ（字上げ分の全角空白を補う）、中央寄せ |
| 傍点（各種） | 圏点（ゴマ点。種類は区別しない） |
| 傍線・波線など | 下線（種類は区別しない） |
| 太字、斜体、○段階大きな／小さな文字、上付き・下付き小文字 | 文字の装飾（1 段階 1.2 倍） |
| 「ママ」の注記 | （ママ）を小さく上付きで添える |
| 割り注 | 括弧付きの小さな文字 |
| 罫囲み（語・範囲） | 枠線。範囲の罫囲みは字下げ・字詰めの幅に合わせる |
| ○字詰め | その字数で折り返す（CSS の最大幅で実現） |
| キャプション、挿絵（○○入る） | 小さめの斜体で中央寄せ。挿絵は［図版：説明］と表示 |
| 改ページ・改丁・改段・改見開き | 2 行分の余白 |
| 縦中横・横組み | 横書きなので何もしない |

## 公開前の確認（現在は未公開）

公開は GitHub Actions（`.github/workflows/pages.yml`）で行います。

- `main` への push（と手動実行）で、`python tools/build_site.py --out _site` を実行します。このスクリプトがテスト（`node --test dev/reader.test.js dev/safety.test.js`、`node dev/aozora.test.js`）と、権利フラグ・重複・本文ハッシュの検証を行い、どれかが失敗すると公開しません。
- 成功したときだけ、生成した `_site/` を GitHub Pages に公開します。リポジトリ全体（`dev/`・`tools/`・README など）は公開しません。
- pull request ではテストとビルドだけを行い、公開はしません。
- 使う環境：Node 24、Python 3.12（どちらも標準機能だけで、追加のパッケージは不要）。
- 最初の公開の前に、リポジトリの Settings → Pages → Build and deployment の Source を「GitHub Actions」にします（「Deploy from a branch」にするとリポジトリ全体が公開されるので選ばない）。

手元で公開物を確かめるとき：

```bash
node --test dev/reader.test.js dev/safety.test.js
node dev/aozora.test.js
python tools/build_site.py --out _site
python -m http.server 8765 --directory _site
```

出力先は未作成のフォルダーを指定します。既存出力を上書きせず、新しい公開候補を作ります。必要な実行ファイルと一覧に含む本文だけをコピーし、ローカル目録の権利フラグ・重複・記録済みハッシュを検証します。`manifest.json` に配布ファイルのサイズと SHA-256 を記録します。生成時には通信しません。公式情報の最新確認・海外の個別権利判断は別途必要です。

公開物だけで行う書き換え（手元のファイルは変えない）：

- **版番号**：`index.html`・`NOTICE.html` の `<span class="build-version">開発版</span>` を、ビルドした日（日本時間）とコミットの短い ID に置き換えます（例 `2026.10.28（1a2b3c4）`。コミットがなければ日付だけ）。GitHub Actions では `GITHUB_SHA` を使います。版は `manifest.json` にも記録します。不具合の報告にはこの版を書いてもらいます。
- **LICENSE**：拡張子のない `LICENSE` は種類不明のファイルとして配信され、リンクを押すとダウンロードになるため、公開物では `LICENSE.txt` としても置き、ページからのリンクをそちらに向けます。リポジトリの `LICENSE` はそのまま（GitHub のライセンス表示に使われる）。

更新直後に新旧のファイルが混ざらないようにする工夫：

- 公開物の `index.html`・`NOTICE.html` では、読み込む CSS・JavaScript・アイコンの URL に内容のハッシュを付けます（例 `reader.js?v=efe94f4528`）。GitHub Pages はファイルを 10 分ほどキャッシュさせますが、中身が変わったファイルは URL も変わるので、新しい HTML がブラウザに残った古い JavaScript を使うことはありません。変わっていないファイルは URL も同じなので、キャッシュはそのまま効きます。ハッシュは公開物にだけ付け、手元の HTML は書き換えません。
- JavaScript が読み込むデータ（`texts/index.json`・`texts/*.txt`・`data/catalog.json`）は、毎回サーバーに更新を確かめます（`cache: 'no-cache'`）。変わっていなければ「更新なし」（304）の応答だけで済みます。
- 残る制約：HTML 自体もキャッシュされるため、更新から 10 分ほどのあいだにページを移動した場合など、古い HTML のまま新しいファイルを読み込むことはまれに起こりえます（GitHub Pages では古い版のファイルを残せないため）。再読み込みすれば直ります。

公開を決めた後に行うこと：

1. 本番 URL を決める。同一 GitHub 所有者のプロジェクトサイトは同一オリジンです。保存名の分離は事故防止であり、別サイトからのアクセスを防ぐには専用オリジンが必要です。
2. 公開候補をコミット等で識別し、以前の公開物を戻せるよう保管する。不具合の報告先は GitHub Issues（https://github.com/manpukuichiro/aozora-yokogaki/issues、NOTICE.html に記載）なので、リポジトリは `manpukuichiro/aozora-yokogaki` の名前で作り、Settings → General → Features の Issues を有効にしておく（新しいリポジトリでは既定で有効）。
3. 対象の Chrome・Edge・Firefox・Safari、キーボード、読み上げ、200% 拡大・狭い画面で確認する。`/repo/` 配下、収録作品 URL、本棚 URL、再読み込み、ZIP/TXT を確認する。
4. Settings → Pages の Source を「GitHub Actions」にしてから `main` に push する（ワークフローがテストと生成の成功を条件に、生成物だけを公開する）。
5. HTTPS を強制し、独自ドメインを使う場合は所有確認・DNS を管理する。実配信の通信量・キャッシュ・圧縮も確認する。

## ブラウザ内の保存と入力の上限

- 保存先は配置ディレクトリごとの IndexedDB / localStorage です。別の端末やアドレスへの自動引き継ぎはありません。
- 本棚の URL は `#book=` を使います。旧 `?book=` も読み取り後に置き換えますが、旧 URL の最初のアクセスはホストへ送信されます。
- 作品の入力・ZIP 展開後・UTF-8 変換後の本文サイズはそれぞれ 5 MiB、30,000 行、一度に 20 ファイルまで。ZIP 内は 256 エントリーまで。構造・サイズ・CRC を検証し、実際の展開量も制限します。ZIP 非対応環境では端末で展開して TXT を開いてください。
- 保存失敗は画面に通知します。ブラウザのデータ消去・プライベート閲覧・容量不足などで保存内容が失われる場合があります。
- 本文のアップロード機能はありません。通信するのは配信元（GitHub Pages）だけで、外部のフォントなどは読み込みません。GitHub Pages のアクセスログについては NOTICE.html を参照してください。
- オフライン起動は保証していません。本文保存とアプリ本体のオフライン配信は別です。
- CSP は、スクリプト・スタイル・フォント・接続をすべて同じサイト（`'self'`）に限ります。外部のサイトから読み込むものはありません。動的な本文装飾のためインラインスタイルは許可しています。meta CSP ではフレーム埋め込み制限等すべての HTTP ヘッダーを代替できません。
